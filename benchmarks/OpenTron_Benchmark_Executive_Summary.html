The memory test runs 2 simultaneous requests of 500 tasks at 500 ms delay.

⚠️ Scope Disclaimer
This is a controlled I/O-wait scheduling benchmark, not an LLM, database, or full multi-agent reasoning workload. It does not establish a general claim about all Python or enterprise frameworks.

Python Implementation Note: Each API process serializes Celery group-result collection through its shared Redis result consumer; task execution remains concurrent. This is part of the measured baseline and contributes to its high-concurrency tail latency.

Deterministic Governance Building Blocks

OpenTron exposes several application-level control points relevant to regulated deployments. They support explicit configuration and state management; they are not, by themselves, a compliance certification or a formal proof of policy correctness.

Control Surfaces

Control Surface Implementation-backed Capability Boundary / Operational Responsibility
Typed contracts Java records define gateway principals and API request/response shapes. GatewayPrincipal validates bounded identity/scope fields and freezes its scope set. Typed boundaries make inputs explicit; they do not prove every business policy or data flow is valid.
Persistent state Default/production configuration supports PostgreSQL, Flyway schema migrations, JPA repositories, and transactional storage services. Desktop mode uses a file-backed H2 database. Backups, retention, access control, and recovery objectives remain deployment responsibilities. The performance benchmark did not exercise the database.
Network & model routing A central network policy gates cloud-model and web-search paths; when outbound internet is disabled, routing selects local Ollama. The policy is stored under ~/.opentron. The default allows internet, cloud routes remain available when enabled, and policy-file I/O failures are currently best-effort rather than fail-closed.
Hardware choice The standard JVM plus PostgreSQL or embedded-H2 deployment does not require confidential-computing hardware. Optional AWS Nitro and GCP CVM profiles are hardware-specific. Local model inference still depends on the configured model and host resources.
Positioning Statement
These controls can support local and on-prem governance without mandatory enclave hardware. The repository and this benchmark contain no head-to-head OPAQUE evaluation, security certification, or evidence of feature parity.

The benchmark measures synthetic I/O scheduling only; it does not test policy enforcement, isolation, database recovery, or regulatory controls.

Implementation sources: Backend configuration, NetworkPolicyService, ConditionalRouter, StorageService, and GatewayPrincipal.

Optional Compliance Profiles

AWS Nitro Enclaves

Isolated microVM with encrypted memory (CPU-exclusive), vTPM attestation, and cryptographic proof of code identity. Profile: aws-nitro

GCP Confidential VM

CPU-protected memory with Shielded VM and vTPM 2.0. Profile: gcp-cvm

Audit Logging

Full request/action logging with correlation IDs for GDPR, HIPAA, and SOC2 compliance. Optional PII detection and redaction.

Encryption at Rest

AES-256-GCM for sensitive data. Keys stored in secure vaults or environment variables, never baked into images.

Conclusion

This benchmark demonstrates that OpenTron's Java 21 virtual-thread design achieves significantly higher throughput and lower tail latency than a FastAPI/Celery/Redis baseline at high concurrency levels, while maintaining comparable idle-state memory consumption. The results are specific to the workload characteristics tested (simulated I/O-bound tasks with 100 ms delay) and do not generalize to all possible deployment scenarios.

The governance building blocks documented on page 2 provide application-level control points for regulated deployments, including optional confidential-computing hardware support, audit logging, encryption, and typed-contract validation. Operators remain responsible for verifying that these controls meet their specific compliance requirements.
